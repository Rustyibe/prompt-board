# 配对契约

本仓库执行的双语配对规则。范围来自 `.doc-pairing.json`；门禁是 `scripts/pairing.py`。

## 一个配对是三个同级文件

```
README.md            英文
README.zh.md         简体中文
README.i18n.yaml     一致性记录
```

不用语言目录，不用中英混排的单一文件。配对整体合并：一次改动不能只落一种语言而不带上另外两个文件。

两种语言地位相同。文档可以先用任意一种语言撰写和评审，对侧由它产出。约束两者的是「必须说的是同一件事」，而不是「谁是原文」。

## 一致性记录

每个含语言相关内容的标题小节对应一条记录，key 是英文标题的 slug 路径（首个标题之前的正文用 `/`）。每条保存该小节两侧正文的截断 SHA-256：

```yaml
/install:
  en: 997430875dc12251
  zh: 541d85f4ca2872ac
```

规则：

- 小节哈希覆盖除围栏代码之外的每个顶层 block；围栏由结构校验逐字节比对，不参与哈希。
- 小节按位置对应：一侧的第 *i* 节对应另一侧的第 *i* 节。
- `write` 重写所指定配对的整份记录。它的 diff 就是「确认一致」这个可评审的动作，所以不指定配对时它拒绝运行。
- 文档定稿后只记录一次。润色中途 `write` 只给评审添噪音。

## 门禁校验什么

`python3 scripts/pairing.py check` 在以下任一情况下失败：

1. **完整性** —— 缺 `.zh.md`；某个中文文件没有英文源；配对存在但从未记录。
2. **记录的哈希** —— 任一侧正文变了却没重新记录。
3. **语言切换链接** —— 中文 H1 之后紧跟 `[English](foo.md) | 中文`，英文 H1 之后紧跟 `English | [中文](foo.zh.md)`。
4. **链接语言版本** —— 中文侧的语料内相对链接仍指向 `.md`，或英文侧指向 `.zh.md`。
5. **结构签名** —— 标题层级与顺序、围栏（info 串和内容逐字节）、表格行列数、列表类型与条目数、有序列表起始值、链接目标。

检查通过只意味着「在这份确切内容上，配对已被确认一致」。意义与完整性、术语、语气、列表和表格内部的顺序，属于评审人那一半的工作，机器不背书。

## 范围

- **要配对：** 根 `README.md`、`docs/` 下每一页。
- **不配对：** `docs/i18n/`（治理文件本身是双语结构）、agent 指令、许可证文本、`.claude/` 下的 skill 内容。

## 更新一个失配的配对

1. `python3 scripts/pairing.py brief README.md` 定位改动小节。
2. 只改动动过的 hunk，最小化补对侧；重译整个文件会丢掉已评审的措辞。
3. 定稿后 `write` 重新记录，`check` 复查。

如果简报报「两侧都改过」，对照简报手工合并；默认没有哪一侧权威。

## CI 接入

pre-commit（只查改动文件）：

```sh
python3 scripts/pairing.py check $(git diff --cached --name-only --diff-filter=ACM \
  | grep '\.md$' | grep -v '\.zh\.md$' || true)
```

CI（全语料，权威）：

```sh
python3 scripts/pairing.py list
python3 scripts/pairing.py check
```

PR 只要改了配对中的任意一侧，就必须在同一次改动里更新对侧并重新记录。

## 配套文件

- `terminology.md`：术语的唯一事实来源，翻译前加载，包括「不要译作」列。
- `style-samples.md`：语体校准基准。样例与成文规则冲突时样例优先；样例与术语表冲突时术语表优先。
